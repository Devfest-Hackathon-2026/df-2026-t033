# フロントエンドと最小バックエンドの接続メモ（修正版）

## 現在の実装

- `frontend/src/App.jsx` から `frontend/src/api.js` の `validateImageWithBackend()` を呼び出します。
- 指紋画像を選択、またはカメラ撮影後に「登録」を押すと、同意済みの場合に限り `POST /api/images/validate` へ送信します。
- Python FastAPIはJPEG/PNG/WebPのファイル形式・サイズ・画像寸法を確認して結果をJSONで返します。**指紋の模様を認識する処理ではありません。**
- 送信した画像はサーバーのDB・画像フォルダには保存しません（multipart処理中の一時領域は利用される可能性があります）。
- 正常受付後、フロント側に画像プレビューが表示され、「個人曲を生成」を操作できます。
- 指紋分類・音楽生成・WAV再生は引き続きブラウザ内のJavaScriptで実施します。
- 共同曲の登録/削除はブラウザ内のセッション状態で管理します。現在のAPIではサーバー上のセッション保存はしていません。

## 実際に使うAPI

| Method | URL | 内容 |
| --- | --- | --- |
| GET | `/api/health` | FastAPI起動確認 |
| POST | `/api/images/validate` | 画像の一時受付と検証 |

リクエストは `multipart/form-data`。フォーム項目は `participant_id=A/B/C`, `consent=true`, `image=<ファイル>`。
正常時 `status=accepted` と画像形式・寸法を返し、失敗時には `status=error`・`code`・日本語 `message` を返します。

## URLの扱い

- ローカル開発：Viteの `/api` プロキシ（`vite.config.js`）が `localhost:8000` のFastAPIに転送。
- Firebase Hosting公開：Cloud Runのサービス名とリージョンに合うように `firebase.json` の `/api/**` リライトを設定してから公開。
- Firebase Hostingだけを公開しても、Cloud Runをデプロイしていなければ画像APIは動作しません。
- CORSの設定を不要にするため、基本的には画面と同一オリジンの `/api` パスで通信します。
