# チームと役割

この文書は公開用です。4人はA〜Dの記号で管理し、氏名、GitHub IDとの対応、連絡先、個人の予定は非公開のチーム連絡手段で共有します。下記の役割は仮案です。

| メンバー | 主担当（仮） | 担当の確定状況 | レビュー相手 |
| --- | --- | --- | --- |
| A | UI/UX | 未確定 | D（案） |
| B | 画像認識 | 未確定 | C（案） |
| C | 作曲・音源化 | 未確定 | B（案） |
| D | バックエンド・接続・提出確認 | 未確定 | A（案） |

Fingerprint Symphonyの[要件定義](07-requirements.md)に担当境界と依存順を記載しています。担当分野は企画に基づき、A〜Dへの対応は割当案です。

- チーム連絡先：非公開の連絡手段で管理し、ここには記入しない。
- 個人の参加予定・進捗共有の時間：チーム内で管理する。
- 提出担当／代行担当：未定／未定
- 判断が割れたときの決め方：候補・理由を記録し、担当者とチームで決定する。

## 作業の進め方

1. 着手前に担当と対象文書をチームへ知らせる。
2. 変更理由と未解決事項を短く残し、1人以上にレビューを依頼する。
3. 同じ文書を同時に編集するときは、編集箇所を分担する。
4. 開始前は[参加前のルール](01-rules.md)の範囲で準備する。
