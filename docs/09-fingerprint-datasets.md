# 指紋データセット調査と取得計画

調査日：2026年11月8日。対象：Fingerprint Symphonyの画像担当。入力は**画面の枠に指先を合わせ、中央を切り出す方式**に決定しています。締切は11月10日17:00です。

**追加調査による更新**：[次の文書](10-additional-dataset-search.md)でCOLFISPOOF（7,200枚）とFAMILY（1,500枚）を追加し、取得優先順位を変更しました。以下は初回調査の記録です。

## 結論

今回の調査範囲では、**申請不要・データ自体の利用条件が明示・商用利用を含む加工と再配布が許諾され・スマホ指先写真に近い・十分な規模**をすべて確認できた候補は見つかりませんでした。「存在しない」という結論ではありません。

直近の取得候補は **JLW-FM-DB_samples（400枚、配布表示110MB、CC BY 4.0）** です。ただし指先のカラー写真ではなくfingermarksのデータで、本番の撮影品質を代表しません。画像処理の動作確認の補助に使い、実際の中央切り出し経路は同意のある自前写真で検証する組み合わせを推奨します。データ本体・アーカイブ内の追加条件・実画像はまだ確認できておらず、取得後の少数確認を採用ゲートにします。[一次配布ページ](https://data.mendeley.com/datasets/ssny74xv48/1)

現在の[推奨方式](08-fingerprint-approaches.md)は学習を必要としないOpenCVの特徴計算です。**大量の訓練データが必要という前提を置かず、検証用と品質しきい値調整用のデータをまず確保**します。学習済みモデルの再学習や新規の深層学習は、残り日程の主経路にしません。

## 2. JLW-FM-DB_samplesで許諾される範囲と限界

CC BY 4.0は適切なクレジット、ライセンスへのリンク、変更表示などを条件に、商用を含む共有・加工を認めます。したがってライセンス上の加工・解析・学習用コピーや公開デモを検討できる候補です。ただし著作権ライセンスはプライバシー等のすべての権利を保証しません。「指紋なので何でも安全」「賞金があるから必ず禁止」とは判断しません。[Creative Commons公式説明](https://creativecommons.org/licenses/by/4.0/)

今回の運用は、画像自体を公開Gitへ置かず、出典・条件・加工手順・集計結果だけを記録する案です。公開デモで画像を表示する必要がある場合は、追加条件を確認してから出典と加工表示を併記します。既存リポジトリのMIT LICENSEで他者の画像まで再許諾したことにしません。学習モデルの公開は別判断とし、画像利用の許可からモデル配布の全条件を推定しません。

出典表示例：

> Chenhao Gao (2021), JLW-FM-DB_samples, Mendeley Data, V1, DOI: 10.17632/ssny74xv48.1. CC BY 4.0. 本作品では中央切り出し・グレースケール化等を実施（実施内容に合わせて更新）。

この400枚について、人物数、独立した指の数、genuine/fake間で同じ指に由来する対応、撮影機材と画像内の注記は未確認です。400枚を400人と数えたり、無作為画像分割で独立性を保証したりしません。画像のsignedという表現を見て署名欄の具体的内容を推測せず、取得後に確認します。

## 3. 次に取得・確認する手順

1. [JLW配布ページ](https://data.mendeley.com/datasets/ssny74xv48/1)でV1、ファイル名 `JLW-FM-DB_sample.zip`、110MB、CC BY 4.0を再確認してダウンロードする。認証や別条件が表示されたら、その内容を確認してから進む。
2. 保存先はリポジトリ内の `docs/local/datasets/jlw/` 等、既存の `.gitignore` で除外される場所に限定する。取得元URL・日付・ファイルハッシュ・ライセンス表示を記録する。実指紋を公開Gitへ追加しない。
3. まずアーカイブの一覧とLICENSE/READMEを読む。展開は必要な少数画像から始め、相対パスに親ディレクトリ移動等がないことを確認する。ページの条件と矛盾があれば採用を止めて問い合わせ候補にする。
4. 各区分から合計8〜12枚程度を確認し、画像の縦横・形式・隆線可視性・背景や注記・切り出し位置を記録する。genuine/fakeを分け、fakeを実スマホ写真の正解データとして扱わない。
5. 対応する人物/指IDの説明を探す。分からない場合は独立評価用の人物分割データとは扱わず、処理の動作・入力異常の確認用に限定する。
6. 採用可能なら最初は50〜100枚程度で特徴抽出の欠損・処理時間・数値範囲を点検する。残りを全部使う前に実機画像との違いを比較する。枚数は短期の作業量案で、十分性の統計的保証ではない。

今回実際に行ったのは一次配布情報と条件の調査までです。ローカル取得は名前解決に失敗し、Web経由のファイルAPIも取得できなかったため、JLWアーカイブ・画像の閲覧は未完了です。**データ本体を取得済み・画質を確認済みとは報告しません。** 数GB規模のデータや学習済み重みのダウンロードも行っていません。

IMPOSEは別配布の[公式Drive](https://drive.google.com/drive/folders/1VYDTTkCG_iCnk-CjsgcqGLngyXOlSIZt?usp=sharing)内のREADME/LICENSEをまず確認する対象です。今回このDriveと例画像を取得できず、データ単体の許諾は確定していません。必要な確認は「生成画像にもApache 2.0が適用されるか」「賞金を含む公開デモ・加工・学習・画像再配布を許可するか」「元データや配布重みに別条件があるか」です。回答待ちの間に主経路を依存させません。連絡や申請は今回送信していません。

## 4. 学習・調整・評価を分ける

| 役割 | 今回必要なデータ | 足りるかの判断 |
| --- | --- | --- |
| OpenCVの方向場・2特徴の計算 | モデル訓練データは不要。典型入力と異常入力の試験が必要 | 出力が有限、欠損が正しく返る、同じ入力で再現、設定変更が追跡できるか |
| 品質しきい値・窓サイズ調整 | 本番と同じ枠/中央cropで撮った明瞭・ぼけ・暗い・反射・枠ずれの写真 | 使える画像を不当に拒否せず、隆線が見えない画像を成功扱いしないか |
| 最終評価 | 調整に使わなかった人物または撮影セッション・撮り直し写真 | 合格/不合格、理由、時間、同じ指の撮り直し変動を記録 |
| 将来の学習モデル | 対象タスクの教師ラベル、十分な独立人物/指、対象端末・照明の分布、使用許可 | データ枚数だけでは決まらない。学習曲線と独立評価が必要。今回新規学習は推奨しない |

学習やしきい値調整をする場合、同じ人物の全指・同じ指の撮り直し・同じ元画像の加工版を同じグループにまとめます。合成データも同じidentityの全姿勢を同じ側へ置きます。画像をランダムに混ぜてから分割すると、似た元画像が調整用と評価用の両方に入るため避けます。

ぼけ・明暗・回転・cropの加工は失敗耐性を見る補助には使えますが、画像を100倍に増やしても独立人物が100倍にはなりません。公開データで良い結果が出ても、実スマホの皮膚反射・焦点・距離・曲面の問題を解決したとは言えません。

## 5. 締切までに現実的に揃えるセット

**推奨する初期目標は公開データ50〜100枚程度の動作確認と、同意を得た実機写真60〜100枚程度の撮影条件確認です。十分な学習データという意味ではありません。** 自前データの例は4〜5人×2指×3条件×2回で48〜60枚に、暗さ・ぼけ・枠ずれなどの失敗例を追加する構成です。各回は指を一度外して撮り直します。本人照合をせず、匿名記号と撮影条件だけで管理します。

可能なら1人以上を調整に使わず最後の確認用に残します。4人だけなら残り3人で調整し1人を確認用にする等、小ささを明記します。少人数で一般的な公平性や精度を保証しません。同意は収集・目的・処理先・保持期間・公開画像の有無を分けて確認し、公開展示への同意を自動的に含めません。

中央切り出しでは「指が枠内にある」と「指紋の線が解像している」は別です。対象スマホ・使用カメラ・画像方向・プレビューと保存画像の座標対応・枠サイズを固定し、実際の本番処理を通したcropを評価します。中央の背景だけでも特徴値を返してしまうことを重点的に確認します。

| 日程案 | 作業 |
| --- | --- |
| 11/8 | JLWの本体条件・少数画像を確認。並行して本番の枠撮影で自前少数セットを集め、隆線が見えるか判断 |
| 11/9前半 | 品質しきい値・2特徴を調整。版を固定して、未使用の人物/撮影回で確認 |
| 11/9後半 | 作曲担当へ特徴と失敗理由を渡し、個人曲→共同曲と削除経路を統合 |
| 11/10 | 条件・限界・サンプル使用・出典を記載。15:00を仮の最終確認、17:00までに提出 |

取得できた公開データが不適合なら、別の大規模モデル学習へ切り替えるより、自前撮影条件と失敗表示を整える方を優先します。デモ用サンプルは常時サンプルと表示し、実撮影の抽出失敗を成功に見せません。

## 調査の到達点

確認対象はMendeley、作者GitHub・大学配布ページ、NIST/Zenodoへの関連候補、作者論文です。判断材料にしたのはデータ配布条件と一次説明であり、第三者まとめ・mirrorのライセンスを許可の根拠にはしていません。本体確認できていない候補が残るため、**候補と取得手順を提示した段階で、十分なデータを確保済みではありません。**
