# 実画像32枚による3分類の小規模実験

追記：[リーク監査・nested group CV](leakage-audit.md)を実施しました。直接混入は確認範囲で検出されませんでしたが、開発27枚のCVは10一致で、以下の5枚4一致を安定性能とは扱えません。

2026-11-08。**実スキャン画像で学習したモデルを作成しました。ただし単独AIの暫定ラベルで、スマホ指写真の性能は未評価です。**

## データとラベル

FAMILY全1,500枚を一覧でスクリーニングしました。Astraが家族1〜80の1,200枚、親エージェントが81〜100の300枚を視認。候補はraw原寸と必要に応じた非生成autocontrast表示で確認しました。一覧スクリーニングは全画像の原寸精査ではありません。

32枚を形態候補として採用：arch 5 / loop 13 / whorl 14。各画像は単独AIレビューで、親とAstraの2人合意や人間・専門家の正解ではありません。archは横断山形・中央突き上げの形態からの候補を含み、tented archとloopの境界や細いdelta等の未確定事項を根拠欄へ残しています。従来の厳密な全構造確認と混同しないよう、`pattern_coverage=morphology_only` とし、明示的なprovisional exportだけで使用します。判別不能な例は採用していません。

前回保留だった境界例1枚も、rawとコントラスト表示を再確認し、**厳密な正解ではなく形態候補として使う実験**へ範囲を変更して採用しました。元レビューは上書きせず、版と理由を新しいローカルCSVへ記録。専門家によるラベル確認が必要です。

## 重複対策と分割

全1,500枚のデコード画素を照合すると、ユニーク画像は1,363枚、重複集合135組、うち別家族フォルダにまたがるものが118組でした。家族フォルダだけで分けると漏洩し得ます。同一画素でつながる家族を推移的に統合し、100家族フォルダを88成分としてから分割しました。これは保守的な出典グループであり、本人の身元や血縁の推定ではありません。近似画像や再スキャンの全検出は保証しません。

| 分割 | 原画像 | 成分数 | arch / loop / whorl |
| --- | ---: | ---: | --- |
| train | 23 | 21 | 3 / 11 / 9 |
| validation | 4 | 4 | 1 / 1 / 2 |
| 新しい評価用 | 5 | 5 | 1 / 1 / 3 |

初回13枚の実験は評価4枚で0一致でした。その結果を見たため、旧評価画像は以後開発用として扱いました。v2では、v1の学習・validation・評価に使っていない成分から新しい評価5枚を確保。画像自体はラベル作成のため視認しています。モデル選択はvalidationだけで実施し、新評価の結果に合わせた追加調整はしていません。

## 方法

全画像に同じ1% autocontrastを適用。薄いraw画像が従来の品質ゲートで拒否されたための明示的な前処理で、線を生成・補完しません。前処理名をモデルに保存し、CLI推論でも同じ処理を自動適用します。コントラストを上げても本来の細部が復元されるわけではなく、背景ノイズを強調する可能性があります。

固定の512次元方向場と線形softmax分類器。trainだけに原画像+4変種（±4/8度、最大3px移動）を与え、115特徴ベクトルで学習しました。白余白を追加し回転後の全範囲を収め、左右反転・90度回転・新しい隆線生成はしません。変種数は独立した指の数ではありません。

クラス不均衡への基本対策としてtrain頻度の逆数によるclass-balanced lossを使用。300epoch中validation loss最小のepoch 2を採用しました。拒否しきい値・特徴距離半径もvalidationだけから設定。全方位回転への耐性や撮影条件の頑健性は未検証です。

## 結果と限界

新評価5枚の暫定ラベルと強制3択が一致したのは**4枚**、macro-F1=0.556。loop 1枚をarchへ誤分類しました。

| 暫定ラベル＼予測 | arch | loop | whorl |
| --- | ---: | ---: | ---: |
| arch | 1 | 0 | 0 |
| loop | 1 | 0 | 0 |
| whorl | 0 | 0 | 3 |

拒否処理込みでは**1枚採用・4枚unknown**、採用1枚は暫定ラベルと一致しました。強制3択の4/5を「実指精度80%」と表示しません。各少数例・選択された標本・AIラベルの誤り・画像形式差のため、一般性能を推定できません。trainの最多クラスloopを常に返す基準は同じ5枚で1一致、macro-F1=0.111です。初回とv2は評価画像が異なり、0/4→4/5を同じ評価条件での改善率とは扱いません。

不一致はloopをarchとした1件です。小さな学習数、固定方向場、位置/回転差、暫定ラベルの曖昧さが考えられますが、原因は切り分けていません。既知の評価例に合わせて特徴やしきい値を修正していません。厳密に確認できたarchだけに限定すると3分割を支える量がなく、**この実験は形態候補ラベルに依存**します。

学習済みモデルは `local/real-run-v2/model.npz`、集計は[metrics JSON](real-v2-metrics.json)。実画像・名前・ラベル生データ・重みはGit除外です。デフォルト推論は `unsupported_domain`、明示オプションでも `experimental/unknown` を維持します。

## 次に必要なこと

archを中心に人がラベルを確認し、独立した例を増やします。さらに、実際の撮影枠によるスマホ指写真を別途集め、撮り直し・ぼけ・空ROIも評価します。現モデルは音楽パイプライン接続の実験には使えますが、安定した3分類器としての採用判断には至っていません。
